# Task 13 — Application Control

## Objective

Configure and validate FortiGate Application Control for Internet traffic from VLAN10 users.

The objectives of this task are:

- Identify applications from real network traffic.
- Understand Application Control categories and application signatures.
- Configure application-specific controls.
- Apply Application Control to an existing Internet firewall policy.
- Verify application detection using real traffic and logs.
- Troubleshoot unexpected application behavior.
- Understand the difference between broad category blocking and granular application control.

### Why Web Client Was Not Blocked

The `Web Client` category contains many browser and web-related signatures.

Blocking the complete category can affect normal browser traffic and unrelated websites.

Therefore, `Web Client` was kept at `Monitor` instead of `Block`.

This allows normal web browsing while still providing visibility into browser-related application signatures.

## Troubleshooting

### Problem

YouTube was configured as `Block`, but YouTube continued to work.

### Evidence

The Application Control logs showed multiple signatures for browser and web traffic.

The `Web Client` category also contained:

- `HTTP.BROWSER`
- `HTTP.BROWSER_Chrome`
- `HTTPS.BROWSER`

### Hypothesis

The YouTube service was generating different network flows that could be classified by different Application Control signatures.

Therefore, blocking the specific `YouTube` signature would not necessarily block every flow used by the service.

### Test

Compare the following configurations:

`YouTube = Block + Web Client = Allow`

versus:

`YouTube = Block + Web Client = Block`

### Result

- Web Client Allow → YouTube worked.
- Web Client Block → YouTube stopped working.

### Conclusion

The behavior was caused by signature-based traffic classification.

FortiGate Application Control should not be understood as a simple model where:

`One Application = One Network Signature`

A service can match multiple signatures.

## Important  Lesson

Application Control is based on traffic signatures.

A specific application signature controls traffic identified by that signature.

A category controls a broader group of signatures.

Therefore:

`YouTube = Block`

is more granular than:

`Web Client = Block`

The second option can have much wider side effects.

## Real-World Scenario

Suppose a company requests:

> Block YouTube for employees but keep Chrome, Edge, Firefox, and normal Internet browsing working.

A bad solution would be:

`Web Client = Block`

because this can block or interfere with normal browser traffic.

The correct approach is to choose a more granular security control according to the business requirement.

Possible approaches include:

- Web Filtering
- URL Filtering
- FortiGuard Web Categories
- Video Filter for more advanced video-specific requirements

Application Control can still be used for application identification and control, but it should not be treated as an endpoint application blocker.

## Troubleshooting Method

The investigation followed:

`Problem → Evidence → Hypothesis → Test → Fix → Verify → Document`

The important lesson was to investigate the actual traffic classification instead of changing security settings randomly.

## Key Lessons

1. FortiGate Application Control is signature-based.
2. One service can match multiple application signatures.
3. Category actions are broader than application overrides.
4. `Monitor` allows traffic while providing visibility through logs.
5. Broad category blocking can cause unintended side effects.
6. Application Control logs are essential for troubleshooting unexpected behavior.
7. Security controls must match the actual business requirement.
8. A specific application requirement should not automatically lead to broad category blocking.
